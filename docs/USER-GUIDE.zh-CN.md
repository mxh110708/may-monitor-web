# May Monitor Web 使用教程

配套基线：Web／Server 0.1.0。本页描述后台和默认前端；公开 May Status 的卡片、地球及图表设置见[主题教程](https://github.com/mxh110708/may-monitor-theme-status/blob/main/docs/USER-GUIDE.zh-CN.md)。

## 登录和初始化

首次安装由操作者持私人 setup 链接进入初始化，设置管理员和站点。链接片段中的 setup Token 只用于该次安装，不是以后登录的密码。完成后使用管理员账号登录；root 密码、Agent Token 和集成只读凭据均不能替代。

找不到密码先查看自己的私人归档和受管恢复流程。不要删除数据库、公开安装链接或将第三方浏览器保存的 Token 当成管理员密码。会话失效与节点离线是不同错误。

## 节点和历史

创建节点后为它安装真实 Agent；逐个检查节点身份、实际版本和报告推进。在线只证明当前连接或有效租约，报告过期要单独处理。CPU 百分比、系统负载、内存和累计流量的口径不同，不能用图表轴或零值掩盖缺测。

选择历史范围后检查实际时间与粒度。服务端保留策略决定可见数据，不是选择七天就一定有七天。切换任务或来源后旧数据不能当作新监测结果。

## 探测与告警

先配置明确目标、协议、参与节点和频率，再观察真实样本。ICMP、TCP、HTTP 的测量阶段不同；Server 向某地区探测不代表用户经过代理的完整路径。

在「监测与告警」设置离线、延迟、失败率、CPU、内存或磁盘规则。明确节点、任务、阈值、窗口、确认、恢复、冷却和维护静默。默认不启用真实投递；缺失、过期和无效样本不能当作恢复。规则的精确限制见[Server 数据与告警](https://github.com/mxh110708/may-monitor-server/blob/main/docs/MONITORING.zh-CN.md)。

通知渠道支持不发送、本地 HTTP 和邮件。本地接收器仅回环；邮件配置由服务器操作者私密安装。后台区分未配置、配置无效和配置就绪，均不展示授权码与收件人。选择邮件并保存规则前应独立核对接收方。配置就绪不保证服务商认证、实际发送或收件箱到达。

## 站点、图标和外观

站点设置管理标题、公开可见范围和图标。默认图标使用原始梅花照片裁剪，可上传替换或恢复默认。公开节点、价格、地址等字段必须按实际期望核对；隐藏后台链接不是访问控制。

安装固定 May Status 后，后台的 managed 外观表单只修改该主题配置。恢复内置界面、更新主题代码或变更锁摘要属于受管维护，不通过打开通用扩展、任意 HTML 或脚本通知来完成。

## 常见错误

| 症状 | 检查 |
| --- | --- |
| 登录成功但没有节点 | 当前节点注册、可见范围、Agent Token 和新报告，而非直接清缓存。 |
| 初始化提示已结束 | 使用正常登录；不要继续使用旧 setup Token。 |
| 图表出现空洞 | 报告时间、任务、保留粒度、鉴权及数据源，不补零。 |
| 管理路由进入公开主题 | 版本与网络模式 Service Worker、真实路由和资源；固定主题不接管 `/admin`。 |
| 页面白屏 | JS／CSS 的响应内容、MIME、404、来源锁；HTML 200 不能当作 JS 成功。 |
| 邮件没有到达 | 规则和渠道、SMTP 状态、事件／重试类别、服务商与垃圾箱。 |

反馈提供准确时间、组件版本、浏览器和脱敏复现步骤。不要提供数据库、完整配置、管理员会话、安装链接或 Token。单次刷新恢复正常不能代替定位原因。
